# Design

## Context

项目为单文件 AutoHotkey v2 脚本 `main.ahk`，运行于 Windows。动机见 proposal.md，行为契约见 `specs/wheel-speed-mode/` 与 `specs/env-configuration/`。约束：不引入 AHK 之外的依赖；滚轮事件拦截与合成滚动均使用 AHK v2 原生能力。

## Goals / Non-Goals

**Goals:**

- 单文件实现，双击/右键运行即可用。
- 速度模式激活期间滚轮"拨动量 → 速度"的油门式手感，反向拨动减速、过零反转。
- hold / tap 两种触发方式，热键与模式均由 `.env` 配置，缺省安全。
- 退出瞬间彻底杀停（无残留定时器、无排队中的合成事件）。

**Non-Goals:**

- 不做 GUI、托盘菜单或配置界面（托盘图标为 AHK 默认行为）。
- 不做速度上限、速度曲线/加速度曲线等高级调控（留待 v2 迭代；`.env` 仅约定 `HOTKEY` 与 `MODE`，速度步长作为脚本内常量）。
- 不支持水平滚轮（WheelLeft/Right）的速度模式。
- 不处理多鼠标设备差异化场景。

## Decisions

### D1: 滚轮拦截方式 — `*WheelUp::` / `*WheelDown::` 热键 + 条件放行

速度模式激活时用 AHK 热键拦截 `WheelUp`/`WheelDown`（带 `*` 通配符以覆盖修饰键状态），在热键回调内更新速度变量后直接返回（不转发原事件）；非速度模式下回调内通过 `Send("{WheelDown}")` 等方式放行原生语义的滚动。

- 备选 A：低级鼠标钩子（`WH_MOUSE_LL` + DllCall）拦截。更底层、可区分真实/合成事件，但复杂度高、单文件内维护成本大，AHK 热键已满足需求。
- 备选 B：`Hotkey` 动态创建/销毁。与静态热键 + 状态标志等价，静态定义更简单且避免动态注册的时序问题。
- **注意**：脚本自身 `Send` 的合成滚轮事件也会触发自身热键钩子。采用 AHK v2 的 `SendLevel`/`#InputLevel` 确保合成事件以更高 `SendLevel` 发出、热键只捕获 level 0 的物理事件，避免自吞循环。

### D2: 持续滚动输出 — `SetTimer` 周期发送

速度模式内以固定周期（约 10–16 ms）的 `SetTimer` 回调按当前速度发送滚轮事件：每 tick 发送的行数 = 速度（行/tick 的整数部分）+ 累积小数部分（亚行精度用累积器实现，保证低速也能平滑滚动）。速度为零时不发送。

- 备选：按需在每次滚轮事件后启动一次性延时滚动。无法表达"持续匀速"，放弃。

### D3: 速度模型 — 有符号速度值 + 线性步进

单一有符号变量 `speed`（正=向下，负=向上）。每次 WheelDown 拨动 `speed += step`，WheelUp 拨动 `speed -= step`；`speed` 过零自然实现反向减速→反转。步长 `step` 为脚本内常量（初值取经验值，实现时按手感微调）。

- 备选：指数/非线性映射。手感更"高级"但引入调参复杂度，首版用线性，规格不约束曲线形状。

### D4: hold 模式检测 — 成对热键（Down/Up 回调）

hold 模式用成对热键：`HOTKEY::`（Down）进入速度模式，`HOTKEY Up::`（Up）退出并杀停。不使用 `KeyWait` 阻塞主线程（会卡住定时器与退出响应）。

- tap 模式只注册 Down 热键，回调内切换状态。
- 热键由 `.env` 的 `HOTKEY` 字符串经 `Hotkey()` 动态注册（无需窗口限定），默认 `MButton`。`MButton` 本身的中键功能在速度模式触发时被热键吞掉（这是触发热键的固有语义，视为预期行为）。

### D5: 杀停实现 — 单一状态机 + 集中清理

退出路径（hold 的 Up 回调 / tap 的切换关闭）统一调用 `ExitSpeedMode()`：`SetTimer(scrollTick, 0)` 停表、`speed := 0`、累积器清零、状态置回普通。所有滚动输出只发生在该唯一 timer 内，保证"停表即无残留"。

### D6: .env 解析 — 自实现轻量解析

用 `FileRead` 逐行解析：trim 后跳过空行与 `#` 注释，按第一个 `=` 分割键值，两侧 trim。只认 `HOTKEY`、`MODE`，未知键忽略。`MODE` 用 `StrLower` 归一后校验 `hold`/`tap`，非法回退 `hold`。文件不存在（`FileExist` 检查）或解析失败均静默走默认值。

- 备选：INI 标准库 `IniRead`。但用户明确要求 `.env` 格式（`KEY=value`），且 INI 需要 section 头，不匹配，放弃。

### D7: 脚本结构 — 单文件分区

`main.ahk` 内按区块组织：配置解析 → 状态变量 → 热键注册 → 模式进入/退出 → 滚轮热键 → 滚动 tick。不拆分模块（单文件是明确需求）。

## Risks / Trade-offs

- [合成滚轮事件被自身热键钩子再次拦截，形成自吞循环] → 用 `SendLevel`/`#InputLevel` 明确分层：物理事件 level 0 被拦截，脚本合成事件 level ≥1 直接放行；实现时以"普通模式下滚轮行为与原生一致"的规格场景做验收。
- [高速滚动时 `Send` 风暴造成输入队列压力或个别应用丢步] → tick 周期不低于 10 ms，单 tick 行数取整发送；必要时用 `SendInput` 模式降低开销。
- [MButton 作为默认热键会吞掉中键原有功能（如自动滚动）] → 属触发热键的固有语义；用户可通过 `.env` 换键。在注释中说明。
- [.env 中 HOTKEY 写了非法热键串导致 `Hotkey()` 抛异常] → 注册时 try/catch，失败回退默认 `MButton` 并以 TrayTip 提示。
- [游戏/全屏应用对合成滚轮事件兼容性不一] → 明确 Non-Goal，不做针对游戏的适配。
- [hold 模式下用户按住期间系统休眠/切换窗口等边缘情况导致 Up 事件丢失] → 退出路径集中化后，任何再次进入/退出调用都会重置状态；必要时可加"物理键状态兜底检查"（实现阶段评估，不影响规格）。

## Migration Plan

全新实现，无迁移。回滚即删除/停用脚本。`.env` 为用户自建文件，脚本缺失时用默认值，不产生副作用文件。

## Open Questions

无——速度曲线形状、步长具体数值等均已在规格中留为实现层自由度（规格只约束"拨动→速度、反向→减速、过零反转、退出杀停"）。
